Comment ça marche

Une action, un mandat, un verdict.

Avant chaque action de l'agent, Aplomb rassemble ce qu'il sait : le mandat signé, les règles du profil, l'avis des moniteurs, les bornes de la session. Il retient le verdict le plus strict, l'applique, puis l'inscrit au journal.

action de l'agent ─▶ profil (outil → effet) ─▶ mandat + règles Cedar ─▶ moniteurs, juge, bornes
                                                                         │
                     journal chaîné ◀── Allow · Review · Deny · Gel ◀────┘  (le plus strict l'emporte)
Aplomb — le cœur de décision

Ce que l'agent a le droit de faire.

Le mandat

Un fichier YAML par projet : la racine du dépôt, les domaines joignables, les branches protégées, le modèle, les serveurs MCP et les bornes de la session. Il porte aussi une intention en langue naturelle, que le juge utilise.

Le mandat est cosigné par deux membres au moins, avec les empreintes des règles. Un mandat ou une règle modifiés sans nouvelle cosignature : le superviseur refuse de démarrer.

id: mon-projet
profil: code
intention: Développer et tester mon-projet, sans rien toucher en dehors du dépôt.
perimetre:
  racine: /Users/moi/code/mon-projet
  domaines_autorises: [pypi.org, files.pythonhosted.org]
  branches_protegees: [main]
bornes: {refus: 5, revues: 20, domaines: 10, envois: 3, actions: 2000}

Les profils

Un profil traduit chaque outil d'un type d'agent en effet : lire, écrire, exécuter, réseau, outil MCP, déléguer. Deux fichiers de règles Cedar : regles.cedar permet ou refuse, revue.cedar désigne ce qui demande un humain. Le premier profil, « agent de code », couvre Claude Code.

Les moniteurs déterministes

  • Provenance : après un contenu non fiable (page web, résultat MCP, fichier hors du dépôt), les actions sensibles passent en revue.
  • Secrets : une clé privée ou un jeton d'API dans une action la met en revue, ou gèle la session s'il quitte la machine.
  • Enchaînements : télécharger puis exécuter, viser par un autre outil une destination refusée, lire un fichier sensible puis envoyer des données.
  • Contrôle croisé : une action qui ne correspond à aucun appel demandé par le modèle est signalée.

Le juge (facultatif)

Un modèle, local de préférence, juge l'écart entre l'action et l'intention du mandat. Il n'est consulté que pour les actions qui comptent (exécution, réseau, MCP, délégation) et sur un échantillon des autres. Ce qui vient de l'agent lui est présenté comme donnée, jamais comme instruction. Sans réponse dans le délai, l'action passe en revue.

Raisonnement et protocoles AI control

Quand le modèle produit un raisonnement explicite, le proxy LLM le lit : une intention de contourner la supervision, d'agir à l'insu des humains ou d'exfiltrer met en revue les actions qui suivent. Deux protocoles peuvent retenir une réponse suspecte avant que l'agent la reçoive : report (defer to trusted, un modèle de confiance répond à la place) et reechantillonnage.

Bornes, gel et délégation

Refus, revues, domaines et envois sont comptés par session ; un dépassement gèle la session. Un sous-agent est jugé par son propre mandat, inclus dans celui du parent, et par le mandat parent : le plus strict l'emporte.

Le hook Claude Code

aplomb hook soumet chaque action avant exécution. Il n'accepte que des réponses signées sur son nonce : un faux superviseur ou un rejeu est refusé. Si le superviseur ne répond pas, l'action est refusée.

Aplomb Gate — les passerelles

Rien ne sort sans passer par là.

Le hook dépend de la coopération de l'agent. Les passerelles, elles, sont sur le chemin du trafic : dans le conteneur, ce sont les seules sorties.

  • Chaque destination est jugée
  • Adresses internes refusées après résolution
  • Envoi plafonné par connexion

Proxy LLM

127.0.0.1:7703 · ANTHROPIC_BASE_URL
  • Seulement vers le modèle du mandat
  • Clé de l'agent retirée, jeton d'Aplomb injecté
  • Secrets masqués avant envoi au modèle
  • Jetons imputés à un compte technique, quotas

Passerelle MCP

127.0.0.1:7704/mcp/<nom>
  • Aplomb lance lui-même les serveurs du mandat
  • Chaque appel d'outil est jugé
  • Définitions épinglées : une description qui change, l'outil est refusé

Quand une passerelle obtient un verdict Review, l'action attend deux minutes la réponse d'un humain dans Aplomb Watch, puis elle est refusée.

Aplomb Watch — voir et répondre

Ce que voient les humains.

Une interface sur la boucle locale (127.0.0.1:7701), réservée aux humains et jamais joignable par l'agent. On s'y connecte par un lien à usage unique.

  • Flux en direct des décisions, avec les compteurs de la session.
  • File de revue : approuver ou refuser une action en attente.
  • Vue chaînée : chaque échange avec le modèle, les outils demandés et les actions réellement exécutées, avec les écarts en rouge.
  • Consommation : jetons par utilisateur, compte technique, prompt et modèle ; contexte et compactions.
  • Gouvernance : indicateurs agrégés, sans rien de nominatif.
  • Boutons : geler, dégeler à quatre yeux, vérifier le journal.

Les comptes sont nominatifs, à clé ed25519, avec trois rôles : lecteur, opérateur, approbateur. Un compte seul peut geler ; dégeler en demande deux.

Mesurer avant de signer

Le banc rouge/bleu.

aplomb evaluer --mandat <mandat> joue 39 scénarios du profil (10 tâches légitimes, 29 attaques) contre le vrai superviseur et rend :

  • la sûreté : la part des attaques bloquées ou mises en revue ;
  • l'utilité : la part des tâches légitimes faites sans humain ;
  • le budget d'audit : le taux de revue du trafic légitime, comparé à ce qu'un humain peut revoir ;
  • le coût du juge.

Chaque cosignature de mandat rejoue le banc et refuse une régression. Sur le mandat d'exemple, sans juge, 80 % des attaques sont arrêtées ; avec le protocole report et un juge factice, 72 % sans aucun humain. Ces chiffres viennent du banc, pas encore de vrais modèles.
